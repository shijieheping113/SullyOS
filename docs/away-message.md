# 离开后消息

用户超过设定的时间没说话，角色就来找用户。一次离开只找一次，用户开口后重新计时。

入口：聊天「＋」→「离开后消息」（`components/chat/AwayMessageSettingsModal.tsx`）。按角色设开关和等待时长，保留 30 分钟到 6 小时的固定选项（默认 90 分钟），也可切换「自定义」，用小时/分钟两列滚轮选择 1 分钟到 24 小时；24 小时时分钟只能为 0。存在 `CharacterProfile.awayMessage` 上（`delayMinutes` 仍存总分钟，`delayMode` 记住固定/自定义选择），导出角色卡时剥掉。读取旧配置时，非预设时长自动显示自定义；非有限或非正数退回默认，正数取整并限制在 1–1440 分钟。纯等待时长与角色时区无关，不改变一次离开只找一次、真实开口后重新计时的规则。

## 两条路，按角色二选一

| 角色状态 | 走哪条 | 用户看到的 |
|---|---|---|
| 开着主动消息 2.0，且配了 Worker | 云端 | 到时间直接收到推送 |
| 其余 | 本地 | 浏览器后台仍可运行时，到点生成并按私聊通知设置提醒；彻底休眠后重新打开补查 |

判定只有一处：`utils/awayMessage.ts` 的 `isAwayCloudRoute`。两条路不叠加：叠加的话云端发过一次，用户上线时本地又补一遍，同一段离开会收到两份。

## 云端

每个角色挂一条云端任务（任务记录上 `away: true`，任务 metadata 带 `amsgAwayMessage` 和 `amsgAwayDelayMinutes`）。

- **谁来维护**：每轮聊天开场（`hooks/useChatAI.ts`，本地生成和即时对话都经过这里）调 `syncCloudAwayTask`，目标时刻是「用户最后一次开口 + 等待时长」。已有任务排得够晚（离目标不到 10 分钟）就不发请求；排早了原地改期；远端已经没有（发过了或被取消）就新建。
- **差的那点谁兜**：worker 到点时用自己知道的最后开口时刻（fire_pack 与在场记录里较新的那份）再算一遍，没到就 `defer` 到该来的时候。推迟不消费任务、不占重试、不留跳过记录。
- **到点必发**：任务是 force 策略，提示词里去掉【开口之前】那段，角色没有「这次不说」的选项。
- **计入连发上限**：它发出去算一次「没回时找你」，到点时也受「没回时最多连着找几次」拦；之后角色自排的接着往上数。每日上限照常管它。
- **不占任务名额**：建它时不查「最多同时排几次」，名额满了也能建。
- **关掉或改了等待时长**：取消云端那条，用户下次开口时按新设置重建。

## 本地

`context/OSContext.tsx` 启动 `utils/awayMessageScheduler.ts`。SW 和网页共用「最后一次真实用户消息 + 等待时长」的单次排期；网页还每 20 秒检查一次，打开页面、切回前台、重新获得焦点时立即补查。所有触发都重新读消息，不能绕过开口改期和已发标记。

用户发消息后（包括关闭自动回复），聊天页请求立即重排；修改开关、等待时长、角色列表也会重排。SW 更换控制器后重新同步排期；SW 只保存角色 ID 与时刻，不保存聊天或 API。`away-sync` 按页面隔离，空清单取消该页面闹钟，`away-trigger` 只通知该页面生成。与 1.0 固定间隔反复生成、Push 加速器无关。

每次检查对开了这项、走本地路的角色逐个判断：

- 用户最后一次开口已经超过等待时长，并且那之后还没补过（补出来的消息 metadata 带 `awayMessage: true`，这是「这段离开补过了」的唯一依据），才补；
- 用户正和这个角色见面或通话时不补；
- 离开越久补的次数越多：每过一个等待时长一次，最多三次。时刻第一次落在等待时长刚满时，其余铺到现在之前。模型一次写完，用 `[[NEXT]]` 隔开各次，每次按自己的时刻落库；
- 生成期间用户回来说了话、关闭功能、修改等待时长或进入见面/通话，过时内容不再保存；分段间也复查；
- 失败后 10 分钟内不再试。

请求用聊天同一套上下文（`buildChatRequestPayload`），提示只进这次请求、不落库。落库走 `applyAssistantPostProcessing`，保留 `metadata.awayMessage`，并用 `awayMessageGapStart` 标识本轮所对应的真实开口时间。生成期间使用现有 KeepAlive；同页互斥，支持 Web Locks 的浏览器还按角色跨标签页互斥。

保存后派发 `active-msg-received`，本地 away 用 `source: local-away` 与云端 push 区分。正文从实际保存的气泡提取，不用未经解析的模型输出。OS 层按 `decideReplyDelivery` 接现有 `chatNotify`：后台即使停留在同一聊天也发带预览正文的系统通知；前台别页只增加未读与页内提示；前台正看该聊天安静。通知尊重私聊开关，点击沿用现有角色跳转。中途某段失败，已保存的句子也通知；未保存的句子不通知。云端 push 原通道不重复发。

拉黑时，away hint 另加当前仍拒收普通消息、普通文字未送达的冷战语境；普通 away 的不汇报、不查岗引导保留。用已读近史判定，不把归档原文加回 API 请求；后处理用保存前近史打未送达，解除后不再给新气泡打标，历史标记保留。求看看和好友申请沿用现有解析，即使整轮只有卡片也计作本段离开已找过，并用保存的卡片正文提供通知预览。

本地闹钟与旧 1.0 一样受浏览器后台运行限制：SW 到点喊网页，网页负责调用 API 和保存。SW 或网页被彻底冻结/结束时无法保证准点，恢复后补查；不能把 SW 闹钟触发当成生成成功。

本地提示保留 1.0 的随手分享生活、自然想起对方、避免汇报和催回复的引导。最近一条真实消息是三小时内的见面记录时，改为分别后的语境；判断包含已归档记录，但不把范围外的见面原文重新放进请求，也不要求模型编造缺失细节。时刻按角色时区表示，关闭时间感知时不报钟。

本轮指令在聊天历史筛选完成后直接插入 API 消息、位于实时状态尾段之前；不再使用 `id: -1` 的假历史消息，因此不会被记忆水位、手动窗口或用户断点过滤，也不会挤掉本应可读的历史。

## 改这块时要一起动的地方

| 改什么 | 位置 |
|---|---|
| 判定、分时刻、切分、要不要改期 | `utils/awayMessageCore.ts`（有单测） |
| 云端维护、本地生成 | `utils/awayMessage.ts` |
| 本地生活分享 / 见面后语境提示 | `utils/awayMessagePrompt.ts` |
| 云端任务的指令文案、metadata 键 | `utils/amsgFireSchedule.ts` 的 `buildAwayTaskInstruction` |
| 到点推迟、计入连发、必发 | `worker/amsg/src/index.ts` 的 `onBeforeFire`；`renderFirePack` 的 `mustSpeak` |

worker 有改动时先部署 worker，并把 `utils/amsgBundleVersion.ts` 往前推一版。
